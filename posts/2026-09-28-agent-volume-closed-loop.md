# AI Agent 的真正杠杆不是单点性能，而是可并行的闭循环

一句话判断：当前 Agent 热潮里，最被低估的不是「更聪明的模型」，而是「能单独闭环、再被大量并行复制」的工作流设计。谁先把这件事做对，谁就先吃到物量红利。

## 事件还原

2026 年 9 月 27 日，日本用户 @AM09_21（高专生，Wakayama）发了一条长帖，核心论点清晰：

> AI Agent 的厉害之处不在单一性能，而在「物量」——把以前「雇人」这种高方差、高成本的扩展方式，变成「买 token + 买机器」这种可预测、可线性放大的扩展。

帖子给出的操作路径是：

1. 给每台机器配一个 Agent；
2. 把任务做成「单独就能跑完」的闭循环（closed loop）；
3. 之后只需要堆 token 和算力，就能横向扩展。

作者进一步指出：正因为闭循环一旦成立就能无限并行，资本与算力充裕的人会迅速拉开差距。于是「寻找更优闭循环」变成了当前最激烈的竞争。

他顺带提到 Meta 的 MuseSpark 在研究侧似乎已经把「算力 + 数据 + 时间」做成可无限缩放的机制，并通过 Contributor 机制把数据端也纳入缩放（来源为「研究者访谈，实际未公开验证」）。同时抛出两个反向问题：

- 什么领域**无法**被物量化？
- 当生产被物量淹没后，消费时间仍是固定的，质量（quality）会不会重新成为瓶颈？而质量一旦被拆成「可微分任务」，是否又会被物量战争吞并？

帖子结尾把「人脉」列为目前最难被 Agent 替代的资产，并建议尽早建立真实连接。

数据侧：截至 9 月 28 日上午，该帖约 1845 likes、180 reposts、48 quotes、20 replies、1634 bookmarks、39 万+ 浏览。互动结构以收藏和转发为主，典型的「方法论沉淀型」热帖。

## 作者与背景

@AM09_21 是日本高专（kosen）学生，粉丝约 2.2 万，日常以日文写技术与 AI 观察。帖子语言口语化、带自嘲，但逻辑链条完整：从「雇人 vs 买 token」的成本结构，推到闭循环设计，再到资本分层与质量瓶颈。

这不是产品发布或模型评测，而是对 Agent 工作流经济结构的直接拆解。

## 方法论拆解：闭循环为什么是杠杆

### 1. 从「人」到「token」的单位变化

传统扩展路径：
- 雇人 → 每月固定高成本 + 招聘方差 + 管理开销 + 离职风险。

Agent 路径：
- 买 token + 买机器 → 边际成本接近线性，结果可预期。

作者把这种转变称为「从ガチャ（抽卡）变成确定性操作」。这是事实判断，不是比喻：token 计量清晰，机器可复制，而人的产出分布宽得多。

### 2. 闭循环是可并行的前提

关键设计约束只有一条：**任务必须能单独跑完**。

如果 Agent A 必须等 Agent B 的人工确认，或必须共享可变全局状态，并行就会立刻塌缩。闭循环意味着：

- 输入明确；
- 工具与环境自包含；
- 输出可被客观验证（测试、编译、评分器、业务规则）；
- 失败可重试而不污染其他实例。

一旦这个闭环成立，后面的扩展就退化成「复制实例 + 加钱」。这与当前 Ralph 类循环、n8n Agents、各类 coding agent harness 的工程方向一致：把「判断」和「执行」拆开，把可验证部分交给循环，把不可验证部分留给人或更高层编排。

### 3. MuseSpark Contributor 作为旁证（未完全核验）

作者提到 MuseSpark 用 Contributor 机制把数据也纳入缩放。公开信息显示：

- Meta 的 Muse Spark 系列（1.1/1.2/1.3）确实提供 Contributor 定价档；
- 该档以极低 token 价格换取「输入输出可用于训练下一代模型」的许可；
- 这确实是一种「用使用量换数据、用数据换下一轮模型」的闭环。

但「无限缩放 + contributor 机制已被验证为研究侧最优」这一点，目前只有作者转述的访谈说法，没有官方论文或技术报告直接支撑。视为假设，而非既定事实。

### 4. 物量之后的质量问题

作者正确指出：生产可以无限堆，消费时间不能。当「能做出来」不再稀缺，「做得好」会重新定价。

他进一步实验「把质量担保拆成可微分任务」。这与当前 self-improving agents 课程（如 Stanford CS329A）强调的「验证器瓶颈」同向：coding 和数学之所以容易自我强化，是因为有编译器/测试/答案可验证；写作、陪伴、开放式设计缺少同等强度的验证器，因此闭循环更难建立，物量优势也更弱。

## 争议与反方

- **「平均开发者从 88ms 到 1.5ms 已经够用」**：Mitchell Hashimoto 的 renderer 实验（2026 年 5 月）显示，Agent 循环能拿到数量级改进，但离手写最优仍差 75×。反方认为，对大多数产品，1.5ms 已足够；正方认为，接受次优会系统性降低行业上限。
- **闭循环是否真能无限？**：对齐失败、工具漂移、环境非平稳、成本爆炸都会打断循环。作者自己也承认「未来不透明」。
- **人脉不可替代**：这是价值判断。事实是：高信任、高模糊、高责任的决策仍高度依赖真人关系；Agent 目前更擅长可验证、可重复的执行层。

## 可迁移的做法

1. **先画闭环，再谈并行**。任何新 Agent 工作流，先问：输入、工具、验证、输出是否能在无实例内闭合？不能闭合的，先别堆实例。
2. **验证器优先于生成器**。把「如何判断做对了」写成可执行规则（测试、schema、业务约束），再让 Agent 循环。没有验证器的领域，物量会放大错误。
3. **预算与实例解耦**。token 与机器按实例分配，失败重试不共享状态，避免一个坏实例污染全局。
4. **质量任务显式化**。把「好不好」拆成可打分的子项（一致性、覆盖、延迟、成本），否则质量永远停留在主观评价，无法进入循环。
5. **保留不可物量化的部分**。人脉、最终责任、模糊目标设定，目前仍应保留在人侧。
